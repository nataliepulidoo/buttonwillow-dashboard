# My Buttonwillow Sales & Weather Dashboard

This is the standalone **React + TypeScript + Vite** dashboard. It contains no
teammate repository, teammate Git history, company workbook or company records.
The original working dashboard and its local workbook remain on this computer.

## What teammates see

The deployed site starts with **Demonstration data — not actual Buttonwillow
sales**. Fictional product names and quantities are generated by `src/demo.ts`.
Forecast, location search and historical weather requests use public Open-Meteo
services; weather is never invented when a request fails.

**Upload data** reads an authorized Excel file into that browser tab. Review the
sheet/column mapping and click **Validate & import** to display its real quantities.
The workbook is never sent to GitHub, Vercel, a weather API or another teammate.
Refreshing restores the demonstration. Uploading once does not share the data
with other visitors. Quantities remain separated by unit; modeling still requires
adequate history, geographic confirmation, complete coverage and validation.

## Run and check

Use Node.js 22.x and pnpm. From this directory:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm preview
```

The build runs the privacy audit, TypeScript, Vite and an output audit. It fails
when private file types are tracked or appear in public assets/build paths.
`pnpm dev` runs a local preview at port 5173. This clean copy does not contain the
original computer-only workbook endpoints.

## Create the Vercel URL

After the code push is approved and completed, import **nataliepulidoo/buttonwillow-dashboard**
at [Vercel New Project](https://vercel.com/new). Use these settings:

| Setting | Value |
| --- | --- |
| Framework preset | Vite |
| Root Directory | `.` (repository root) |
| Node.js | 22.x |
| Install Command | `pnpm install --frozen-lockfile` |
| Build Command | `pnpm build` |
| Output Directory | `dist` |
| Environment variables | None for demonstration mode / local browser imports |

`vercel.json` records the install/build/output settings. Choose **Deploy** and
share the HTTPS URL Vercel returns. `http://localhost:5173/` is not a deployed URL.
Do not assume the old classroom demo belongs to this project.

In Vercel **Deployment Protection**, enable authentication and invite the intended
teammates. Verify whether the selected plan/protection covers the production
domain as well as previews; a GitHub repository's privacy does not secure a
website. Avoid bypass links for confidential work. Confirm the exact domain is
approved before importing any company file into the browser.

The browser needs outbound HTTPS to `api.open-meteo.com`,
`archive-api.open-meteo.com`, and `geocoding-api.open-meteo.com`. No API key is needed
for eligible noncommercial use. Business use needs an Open-Meteo licensing review;
keep future commercial keys server-side, outside client code.

## Automatically sharing the same private sales numbers

This is not configured yet. Company approval, protected storage and access control
are required; copying the workbook into GitHub is never the solution.

Use a company-approved private database/object store and server-side ingestion of
approved product/date/quantity/unit/location fields. Add company sign-in and
server-side authorization for each team's warehouses/products. Return only
authorized aggregates from a runtime API with `Cache-Control: private, no-store`;
never put the workbook or full transaction extract into static HTML or bundles.
Store database/auth secrets as **server-only** Vercel environment variables, never
`VITE_*` variables. Configure login callback URLs, retention and access reviews.
Do not put sales rows or storage keys into the browser bundle.

No shared-data API, login provider or storage credentials are implemented in this
static version. Adding environment variables alone will not connect it. Keep
demonstration data until that separately reviewed integration is ready, or have
each teammate import only data they are authorized to use in their own tab.
